架构与生命周期

一套管理协议，两套业务合同

Surface、消息连接器和数据源连接器共享发现、进程、配置、健康、修复和事件确认，但消息与数据资源不是同一种业务，不应被压成一个通用 JSON 动作。

Manifest 是安装合同

字段说明
schema / id / version / kind稳定身份与类型；ID 使用配置和状态命名空间
runtimeOneShot 或 Managed、artifact、driver profile 与 transport
capabilities可发现的业务能力，不代表当前健康
routes / resources回调路由或静态资源挂载
health / config_schema健康探测、修复参数与必需配置
default_enabled首次安装默认启用意图；运行状态仍由 Gateway 保存

状态与自动修复

运行态包括 discovered、starting、ready、degraded、restarting、unavailable、disabled、failed 和 circuit-open。失败被分类为 manifest、entry、spawn、exit、health、protocol、auth、network 等类型；Supervisor 只在修复策略允许时重启，超过窗口阈值后打开 circuit，避免无限拉起。

配置重校验与有界重启

Managed Edge 配置变更必须先重新校验；只有合同支持时才对现有实例执行 configure。artifact、driver profile、transport 或安装内容变化进入 Supervisor 管理的有界 restart/reload，并受退避与 circuit 策略约束。无效配置保留当前可用实例，并向 Gateway 状态面报告拒绝原因。

增加新 Edge 单元

  1. 先选择业务域：Web Surface、Message、Source 或 Automation，不创造模糊的“万能 connector”。
  2. 复用 edge-contract v2 DTO；缺少业务语义时扩展对应域合同并同步生成 Core 副本。
  3. 在 driver-profiles.json 注册逻辑实例与 artifact，不复制相同 SDK 运行实现。
  4. 添加 surface.json、配置 schema、健康语义、失败分类与合同测试。
  5. 在 Gateway 真实进程测试发现、启动、握手、动作、事件 ACK、重启和清理。
