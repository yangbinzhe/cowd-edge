消息连接器

渠道负责消息，Runtime 负责对话

消息连接器把平台身份、消息、媒体与回调归一化为 Edge 事件。Gateway 负责可靠接纳并选择或创建 Session，Runtime 负责 Task 路由和回答，回复再经 outbox 送回原渠道。

端到端消息链

platform event / long connection
  → connector normalize + platform dedup key
  → Gateway SurfaceHost inbox (received)
  → identity binding + Session admission
  → Runtime Task / Execution
  → durable answer and evidence
  → SurfaceHost outbox
  → connector send / edit / media upload
  → delivery receipt (replied | retry | DLQ)

平台的 typing、reaction 或 processing 状态是消息生命周期的附属状态。正常回复、失败、取消和超时都必须清理，不能让已完成消息继续显示“处理中”。

渠道会话与 Cowd Session

  • 连接器提供稳定的平台 account/chat/user/message 标识；Gateway 维护它们到 Cowd Session 的绑定。
  • 默认 `session_reset: none` 时，同一渠道会话持续复用；daily、idle、both 或 always 可显式改变重置策略。
  • 归档不等于遗忘。历史消息和 Task/Mission 绑定仍耐久保存，重新激活时按索引与热尾段恢复。
  • 渠道不能自己生成第二套 Session ID 或绕过 Gateway 直接调用 Runtime。

附件与媒体

连接器负责下载或上传平台媒体并返回规范化附件描述，Gateway 的资源层负责统一存放、配额、哈希、元数据和授权引用。图片可直接交给支持视觉的模型；其他文件由模型根据已有 Tool、Skill、Plugin 或 MCP 能力选择解析路径。连接器不内置文档业务操作。

失败与修复

位置证据处理
接收失败平台事件 ID、协议错误、连接状态重连或 callback 重试，不创建重复 Session 输入
Runtime 失败Execution、Activity、Provider/Tool evidence保存失败终态并发送诚实回复或等待批准
回复失败outbox、attempt、平台响应有界退避；最终进入 DLQ，支持人工重放
